# Workflow inventory — the checked-in contract between .github/workflows/
# and branch protection. Enforced by scripts/check_workflow_inventory.py.
#
# WHY: branch protection requires status-check CONTEXTS by name. A context
# is just a string; GitHub has no idea which workflow is supposed to emit
# it. Rename or delete the emitting job and the requirement silently
# becomes unsatisfiable — every PR waits forever on a check that will
# never post, and the only way to merge is an admin override. That is
# exactly what happened between #2551 and 2026-07-31: the required context
# "CI Status Gate" was emitted by nothing at all.
#
# Two sections, both enforced:
#
#   [workflows]        every .github/workflows/*.yml file, one per line.
#                      Adding, renaming, or deleting a workflow without
#                      updating this list fails CI.
#
#   [required-contexts] every context in the `main` branch-protection
#                      required list, one per line. Each MUST be emitted
#                      as a job `name:` by some workflow, and that
#                      workflow MUST run on every pull request (a
#                      `pull_request:` trigger with no `paths:` /
#                      `paths-ignore:` filter) — otherwise the check
#                      cannot post on PRs that miss the filter and the
#                      requirement is unsatisfiable for them.
#
# Changing branch protection is a settings-UI action. When you change it,
# update [required-contexts] in the SAME PR so the guard keeps matching
# reality. See docs/runbooks/BRANCH_PROTECTION.md.
