# Playwright CLI Skill

Drive a real browser from the terminal using `playwright-cli`. Prefer the bundled wrapper script so the CLI works even when it is not globally installed.
Treat this skill as CLI-first automation. Do not pivot to `@playwright/test` unless the user explicitly asks for test files.

## Prerequisite check (required)

Before proposing commands, check whether `npx` is available (the wrapper depends on it):

```bash
command -v npx >/dev/null 2>&1
```

If it is not available, pause and ask the user to install Node.js/npm (which provides `npx`). Provide these steps verbatim:

```bash
# Verify Node/npm are installed
node --version
npm --version

# If missing, install Node.js/npm, then:
npm install -g @playwright/cli@latest
playwright-cli --help
```

Once `npx` is present, proceed with the wrapper script. A global install of `playwright-cli` is optional.

## Skill path (set once)

```bash
export CODEX_HOME="${CODEX_HOME:-$HOME/.codex}"
export PWCLI="$CODEX_HOME/skills/playwright/scripts/playwright_cli.sh"
```

User-scoped skills install under `$CODEX_HOME/skills` (default: `~/.codex/skills`).

"$PWCLI" open https://playwright.dev --headed

## Core workflow

1. Open the page.
2. Snapshot to get stable element refs.
3. Interact using refs from the latest snapshot.
4. Re-snapshot after navigation or significant DOM changes.
5. Capture artifacts (screenshot, pdf, traces) when useful.

Minimal loop:

```bash
"$PWCLI" open https://example.com
"$PWCLI" snapshot
"$PWCLI" click e3
"$PWCLI" snapshot
```

## When to snapshot again

Snapshot again after:

- navigation
- clicking elements that change the UI substantially
- opening/closing modals or menus
- tab switches

Refs can go stale. When a command fails due to a missing ref, snapshot again.

# RegEngine Runner & Debug

> Verified against `main` @ `a655670` (2026-07-14). RegEngine is a **consolidated FastAPI
> monolith** (`server/main.py`) + Next.js 16 frontend. The old 6-microservice runtime described in
> earlier versions of this skill no longer exists in production. Former service directories remain
> as code seams; their `main.py` entrypoints are debug-only.

## Running the app

```bash
# From project root — THE production-shaped way to run RegEngine locally:
export PYTHONPATH=$(pwd):$PYTHONPATH
uvicorn server.main:app --host 0.0.0.0 --port 8000 --reload

# Production-equivalent (what the container runs):
bash scripts/run-migrations.sh && \
gunicorn server.main:app --worker-class uvicorn.workers.UvicornWorker \
  --workers ${WEB_CONCURRENCY:-4} --bind 0.0.0.0:${PORT:-8000}

# Frontend:
cd frontend && npm run dev   # port 3000, proxies backend via /api/proxy
```

Legacy per-service entrypoints (`services/<name>/main.py`) still start standalone apps for
focused debugging, but routes/behavior can differ from the monolith mount — prefer
`server.main:app` unless you specifically need isolation.

## Environment

## Router surface (which endpoints exist)

`server/main.py` mounts: always-on core (`/health`, `/readiness`, `/metrics`, status, document
ingestion, **webhooks**, FSMA-readiness compat) + every feature router unless disabled.

- `DISABLED_ROUTERS=name1,name2` — disable by name (typos are logged as warnings).
- `_EXPERIMENTAL_ROUTERS` (auto-OFF in production unless `ENABLE_EXPERIMENTAL_ROUTERS=true`):
  scraping, discovery, sources, sandbox, sensitech, audit, sop, export, qr_decoder, label_vision,
  exchange, recall_simulations, graph, nlp.
- Reference: `docs/engineering/ROUTER_SURFACE.md`.

Key production-default feature routers: csv, edi, epcis_ingestion, inflow_workbench, fda_export,
proof_verify, score, portal, billing, alerts, onboarding, recall, supplier_mgmt, audit_log,
product_catalog, team_mgmt, settings, integration.

## Health checks

```bash
curl -s localhost:8000/health | python -m json.tool      # liveness
curl -s localhost:8000/readiness | python -m json.tool   # deep probe
```

`/readiness`: **Postgres required (503 if down)**; Redis probed but non-fatal; Neo4j probed only
when the graph subsystem is mounted, else reported `not_probed`.

## Background work

In-process: `server/workers/embedded_scheduler.py` + `task_processor.py`; pg_notify-based task
queue (no Kafka in the deployed path). Scheduler status: `/v1/scheduler/status` and
`server/routes_scheduler_status.py`.

## Docker Compose

`docker-compose.dev.yml` is the checked-in dev stack. Check the file before assuming which
dependencies it starts.

## Common startup failures

| Symptom | Likely cause | Fix |
|---|---|---|
| `ModuleNotFoundError: shared` / `services` | PYTHONPATH not set | `export PYTHONPATH=$(pwd):$PYTHONPATH` from repo root |
| `ConnectionRefusedError` on 5432 | Postgres not running | start Postgres (compose or local) |
| `/readiness` 503 | DB down or migrations missing | `bash scripts/run-migrations.sh` |
| Router missing in prod | it's in `_EXPERIMENTAL_ROUTERS` | set `ENABLE_EXPERIMENTAL_ROUTERS=true` (non-prod) |
| `DISABLED_ROUTERS` typo warning | name doesn't match a router | check names in `server/main.py` |
| `address already in use` | port conflict | `lsof -i :8000` |

## Middleware stack (per request)

Request ID → security headers → rate limiting (`RateLimitHeadersMiddleware`) → observability
(OpenTelemetry) → CORS → request safety. Logs are structlog JSON — pipe through `jq` to read.
